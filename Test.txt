1. COMPTES UTILISATEURS & AUTHENTIFICATION
================================================================================

1.1 Inscription par email
    Test : Un utilisateur s'inscrit avec email + mot de passe.
    Données : POST /api/register { email: "test@exemple.com", password: "12345678", password_confirmation: "12345678" }
    Attendu : 201, message "Code envoyé par email", OTP stocké en base.

1.2 Vérification email (OTP)
    Test : L'utilisateur soumet le bon OTP.
    Données : POST /api/verify-otp { email: "test@exemple.com", otp: "123456" }
    Attendu : 200, token Sanctum, email_verified_at != null.

1.3 Renvoi OTP
    Test : L'utilisateur demande un nouvel OTP.
    Données : POST /api/resend-otp { email: "test@exemple.com" }
    Attendu : 200, nouveau OTP envoyé.

1.4 Connexion classique
    Test : L'utilisateur se connecte avec email + mot de passe.
    Données : POST /api/login { email: "test@exemple.com", password: "12345678" }
    Attendu : 200, token Sanctum.

1.5 Complétion profil
    Test : Après connexion, l'utilisateur complète son profil.
    Données : POST /api/profil/complete { name: "Jean", tel: "771234567" }
    Attendu : 200, nom et téléphone mis à jour.

1.6 Forgot password
    Test : L'utilisateur demande un lien de réinitialisation.
    Données : POST /api/forgot-password { email: "test@exemple.com" }
    Attendu : 200, email reçu.

1.7 Reset password
    Test : L'utilisateur réinitialise son mot de passe.
    Données : POST /api/reset-password { token: "...", email: "...", password: "newpass", password_confirmation: "newpass" }
    Attendu : 200, mot de passe changé.

1.8 Connexion via réseau social (Google)
    Test : L'utilisateur clique sur "Se connecter avec Google".
    Données : GET /api/auth/google/redirect
    Attendu : Redirection, puis callback, token généré.

1.9 Consultation profil
    Test : L'utilisateur connecté consulte son profil.
    Données : GET /api/profil (avec token)
    Attendu : 200, informations utilisateur + badge.

1.10 Modification profil
    Test : L'utilisateur modifie son nom.
    Données : PUT /api/profil { name: "Jean Dupont" }
    Attendu : 200, nom mis à jour.

1.11 Changement mot de passe
    Test : L'utilisateur change son mot de passe.
    Données : PUT /api/profil/password { current_password: "old", password: "new", password_confirmation: "new" }
    Attendu : 200, mot de passe mis à jour.

1.12 Déconnexion
    Test : L'utilisateur se déconnecte.
    Données : POST /api/logout (token)
    Attendu : 200, token révoqué, status = "desactive".

5. EMPRUNTS & RETOURS
================================================================================

5.1 Emprunter un livre (exemplaire disponible)
    Test : L'utilisateur emprunte un livre disponible.
    Données : POST /api/loans { book_id: 1 }
    Attendu : 201, loan créé avec status "en_attente_de_retrait", pickup_deadline = now+24h.

5.2 Emprunter un livre (aucun exemplaire disponible)
    Test : L'utilisateur emprunte un livre sans exemplaire dispo.
    Données : POST /api/loans { book_id: 1 } (nb_available=0)
    Attendu : 202, status = "réservée", ajouté en file d'attente.

5.3 Limite d'emprunt atteinte
    Test : L'utilisateur dépasse sa limite (badge Bronze = 2).
    Données : POST /api/loans 3 fois
    Attendu : 403, message indiquant la limite.

5.4 Empêcher doublon d'un même livre
    Test : L'utilisateur tente d'emprunter le même livre deux fois.
    Données : POST /api/loans (même book_id) deux fois
    Attendu : 422, "Vous avez déjà un exemplaire".

5.5 Blocage si pénalités impayées
    Test : L'utilisateur a une pénalité non payée.
    Données : POST /api/loans
    Attendu : 403, message "pénalités non payées".

5.6 Confirmation retrait (pickup) par staff
    Test : Un bibliothécaire confirme le retrait.
    Données : POST /api/loans/{loan}/confirm-pickup
    Attendu : 200, status = "en_cours", loan_date = now, copy.status = "emprunté".

5.7 Retour de livre (sans retard, sans pénalité)
    Test : Retour avant expected_return_date.
    Données : POST /api/loans/{loan}/return { return_copy_state_id: 1 }
    Attendu : 200, status = "retourné", score + points, nb_available++.

5.8 Retour avec retard (pénalité automatique)
    Test : Retour 5 jours après expected_return_date.
    Données : POST /api/loans/{loan}/return { return_copy_state_id: 1 }
    Attendu : Pénalité = 5 * daily_penalty_amount, status = "non_payé".

5.9 Retour avec pénalité manuelle (livre endommagé)
    Test : Le bibliothécaire ajoute une pénalité supplémentaire.
    Données : POST /api/loans/{loan}/return { return_copy_state_id:3, additional_penalty_amount:2000, penalty_reason:"Page déchirée" }
    Attendu : Pénalité totale = retard + 2000.

5.10 Annulation automatique (non retiré dans 24h)
    Test : Un loan en "en_attente_de_retrait" dépasse pickup_deadline.
    Données : Exécuter php artisan loans:cancel-expired-pending
    Attendu : status = "expiré", copy.status = "disponible" (ou attribué à la file).

5.11 File d'attente : attribution automatique
    Test : Un exemplaire devient disponible, un loan "réservée" existe.
    Données : Retour d'un livre alors qu'une réservation existe.
    Attendu : Le loan réservé passe à "en_attente_de_retrait", notification envoyée.
